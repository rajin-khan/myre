# Pick a tiny thing to build

Once we can explain an idea, we can try turning it into something small.

Choose one job, such as printing a message at startup, listing a few files, or showing which programs are running. Keep the first version small enough that the group can read every line and explain what it does.

Write down what the program should do before choosing tools. Then build the smallest version, try it in a safe place, and keep notes about what worked.

## Pick a first build

- What should it do?
- What is the smallest useful version?
- What will we use to test it safely?
